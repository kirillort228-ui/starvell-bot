# Starvell Telegram Bot — API version

Telegram-бот для уведомлений, продаж и автоматических сообщений Starvell.
Интеграция использует внутреннее HTTP API сайта с авторизацией через Cookie.
Отдельный API-ключ Starvell не требуется. Это не документированное публичное API:
сайт может менять его контракт.

## Что изменено

- Чаты: `POST /api/chats/list`, с пагинацией.
- Текущий аккаунт: `GET /api/profiles/me`.
- Продажи: `POST /api/orders/list`, `filter.userType=seller`, с пагинацией.
- История сообщений: `POST /api/messages/list-v2`, пагинация через `beforeId`.
- Каталог продавца: `POST /api/catalog/list-user-profile-offers`.
- Профиль: `GET /api/profiles/{username}`.
- Отправка сообщений: `POST /api/messages/send`.
- Прочтение: `POST /api/chats/read`.
- Поднятие: `POST /api/offers/bump`.
- Открытые заказы: `POST /api/chats/list-open-order`.
- Данные чата: `POST /api/bff/chat-page`.
- Отметка выполнения продавцом: `POST /api/orders/{id}/mark-seller-completed`.

Клиент не загружает HTML и `/_next/data`, не ищет buildId и не перебирает
предполагаемые маршруты. `pageProps` в возвращаемых Python-словарях — локальный
адаптер для существующих экранов Telegram, а не запрос к Next.js.

Потеря сессии и неизвестный формат ответа показываются как ошибка. Фоновая
проверка читает историю новых сообщений, а точка отсчёта сдвигается после
обработки. Автоответы и уведомления имеют отдельные маркеры повторной отправки.
Это не гарантия exactly-once: при разрыве соединения после принятия сообщения
сервером результат может остаться неизвестным.

## Запуск

Нужен Python 3.10 или новее.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

В Windows активация: `.venv\Scripts\activate`; копирование: `copy .env.example .env`.
Заполни `BOT_TOKEN` в `.env` токеном своего бота от BotFather, затем:

```bash
python bot.py
```

Существующая SQLite-база совместима: перед обновлением останови старый процесс,
сделай резервную копию базы и сохрани DATABASE_PATH. Одновременно запускай один
экземпляр бота. На хостинге файл базы должен находиться на постоянном диске.

## Подключение Starvell

1. Войди в свой аккаунт Starvell в браузере.
2. Открой DevTools → Network → Fetch/XHR и обнови страницу чатов.
3. Выбери запрос к `/api/`, например `/api/chats/list` или `/api/profiles/me`.
4. Скопируй значение заголовка запроса `Cookie`.
5. В Telegram открой «Мои аккаунты» → «Добавить аккаунт» и передай Cookie.

Cookie даёт доступ к аккаунту. Не публикуй его, `.env` и SQLite-базу. База хранит
Cookie и пароли прокси открытым текстом. Прокси настраиваются отдельно для аккаунта;
поддерживаются HTTP/HTTPS/SOCKS5. При истечении сессии аккаунт нужно переподключить.

Команда `/api_check` проверяет профиль и список чатов через API без изменения
заказов. Она не выполняет отправку сообщения и не подтверждает заказы.

## Функции и ограничения

- Уведомления о непрочитанных сообщениях, просмотр продаж и профиля.
- Приветствия, автоматические тексты по событиям и автовыдача сохранённого текста.
  Склада одноразовых ключей и передачи файлов нет. При выдаче ценных товаров
  отдельно проверь соответствие событий и статусов своему типу заказа.
- Напоминания по выбранному чату работают с активными продажами старше 24 часов.
  Расписание использует UTC; повторная отправка учитывает сохранённый период.
- Поднятие использует категории собственных активных товаров из API; старый
  статический каталог не отправляется на сервер. Если сохранён выбор товаров,
  поднятие ограничивается им.
- Автоподтверждение отмечает выполнение **продавцом**, а не получение покупателем.
  Включай его только для подходящих товаров: оно не проверяет факт внешней выдачи.
- Кнопка «Прочитать все» действительно отмечает чаты прочитанными на сайте.
- «Вечный онлайн» остаётся сохранённой настройкой: поддержание присутствия не реализовано.
- Общий топ продавцов недоступен: его API не подтверждено. Поиск профиля сохранён.
- Статистика показывает продажи подключённого аккаунта. Формула комиссии 2,9%
  сохранена из исходного бота; её соответствие своему тарифу нужно проверить.
- Платёжная логика Crypto Pay и подписки сохранена из исходного проекта.

## Проверки

```bash
python -m unittest discover -s tests -v
python -m compileall -q bot.py chat_watcher.py starvell_client.py
```

Тесты используют HTTP-заглушки и временную базу: проверяют пагинацию, контракт API,
потерю авторизации, историю сообщений, повтор после ошибки Telegram, напоминания
и сохранение настроек. Они не обращаются к реальным аккаунтам и не проводят оплату.

Маршруты и DTO сверены с JavaScript Starvell. Без Cookie владельца не проверен
полный авторизованный сценарий. После установки сначала выполни `/api_check`,
затем проверь уведомление на тестовом чате. Поднятие и автоподтверждение проверяй
отдельно на тестовых товарах и заказах.
